## 0.7.0 on 2026-11-04

### Changed

* The DSQL schema drops the unused activity_state table and its three indexes; apply the migration with tkr schema setup.
* Projection metrics now describe passes, replacing the checkpoint and worker lag metrics, and the ProjectionCheckpointLag alert is now ProjectionLagHigh.
* A tokeirad without a placement controller now refuses to start while another holds its DSQL cluster, and after a crash its replacement waits up to six minutes.
* The first start after upgrading copies the visibility attribute index into a new layout before serving, taking longer the more attributes a cluster holds.
* The visibility projector now applies runs in different rollup stripes concurrently, so List and Count catch up sooner under load.
* Controller-managed clusters need a peer credential file on every node: generate one with tokeirad, stop every node, and set it in each node's configuration before restarting.
* An open run from an earlier release recovers its completed updates when it loads, unless it was reset before 0.6.0; until its next commit, each load rereads its history.
* Deliver activities through bounded queue-home discovery and fenced execution-owner starts, with durable request receipts for lost replies and complete acquisition repair.
* Upgrade with every node stopped: apply migrations V128–V132 and use TKW4/snapshot-8 capable binaries throughout.
* Remove BacklogConfig, RuntimeConfig.backlog and max_dispatch_reconciliations_per_scan settings.
* The legacy backlog table remains for bounded conditional disposal.
* Older binaries cannot read TKW4 state; rollback requires a compatible binary or restoration of the pre-upgrade database, not an in-place schema downgrade.
* Upgrade a DSQL database that holds runs with every writer stopped, then run `tokeirad storage outbound-recovery` plan and apply; see docs/operations/outbound-recovery-cutover.md.

### Fixed

* Visibility counts stay exact when an apply fails partway, and grouped counts no longer fail on DSQL.
* A workflow start no longer strands its first workflow task when its reserved poll meets other work or its deadline, or when the start's caller gives up.
* On DSQL, a run's state or history batch that encodes to more than 1 MiB is now stored in parts, so its commit, reads, reset and deletion succeed.
* List and Count no longer miss transitions or stop updating, and the projection log no longer grows without bound.
* A run's TemporalUsedWorkerDeploymentVersions list follows Temporal v1.31.0's rules from its next workflow task completion.
* Workflow dispatch repair now rejects stale owners after lease takeover or release while allowing compatible lease renewal.
* A run whose search attributes need thousands of index rows now appears in List and Count, instead of its visibility staying stale.
* On DSQL, a standalone activity's state or a worker invocation request that encodes to more than 1 MiB is now stored in parts, so its writes and reads succeed.
* An update to a paused, failing or closing workflow is refused as Temporal v1.31.0 refuses it, and a worker message for a completed update fails the workflow task.
* On DSQL, visibility images and memos over 1 MiB are now stored in parts, so commits, projection applies and visibility reads preserve the whole value.
* Continue-as-new, retry and cron successors are now written with their run’s close, so a crash or a drain no longer ends the chain.
* Workflow successors now preserve the correct metadata, failure and last-result fields, continue cron after exhausted retries, and honor minimum start delays.
* Workflow outbound work survives restarts and ownership changes; resets publish complete state, and oversized successors retain their execution chain.
* Validate timeouts and delays as Temporal does: refuse negative values and cap long ones at 100 years.
* A visibility read or write cancelled while starting its transaction no longer leaves that transaction open on a pooled connection.
* Deleting a workflow run on DSQL now removes all of its rows; earlier versions could leave part of its history behind.
